# 외부 데이터 출처

Earth가 쓰는 외부 데이터와 서비스를 정리한다. 각 항목마다 무엇을 어디서 받는지, 언제 받는지,
라이선스, 실패하면 어떻게 되는지를 적는다. 새 출처를 붙이거나 바꿀 때 이 문서를 같이 고친다.

받는 시점은 세 가지다.

| 시점 | 뜻 | 예 |
| --- | --- | --- |
| 빌드 시점(정적) | 미리 받아 저장소에 넣었다. 실행 중에는 외부에 나가지 않는다 | 지구 텍스처, 국경 |
| 실행 중 · 서버 | 백엔드가 받아 가공해 둔다. 브라우저는 우리 서버만 본다 | 실시간 구름 |
| 실행 중 · 브라우저 | 브라우저가 외부에 직접 요청한다 | 지도 타일, IP 위치 |

## 실시간 구름: 정지궤도 위성 다섯 기 합성

지구를 한 바퀴 두르는 정지궤도 기상위성 다섯 기의 적외선(약 10.4 µm) 영상을 10분마다 받아 한 장으로 합친다.
원본 수치 파일이 아니라 각 기관이 웹 지도 서비스(WMS)로 공개하는 단일 채널 영상을 쓴다. 서버가 위경도 격자로
재투영해 주고, 라이선스도 이쪽이 자유롭다(아래).

| 위성 | 직하점 경도 | 받는 곳 | 레이어 | 간격 |
| --- | --- | --- | --- | --- |
| GOES-West | 137.2°W | NASA GIBS WMS | `GOES-West_ABI_Band13_Clean_Infrared` | 10분 |
| GOES-East | 75.2°W | NASA GIBS WMS | `GOES-East_ABI_Band13_Clean_Infrared` | 10분 |
| Meteosat-12 (MTG) | 0° | EUMETSAT EUMETView WMS | `mtg_fd:ir105_hrfi` | 10분 |
| Meteosat IODC | 45.5°E | EUMETSAT EUMETView WMS | `msg_iodc:ir108` | 15분 |
| Himawari | 140.7°E | NASA GIBS WMS | `Himawari_AHI_Band13_Clean_Infrared` | 10분 |

```
https://gibs.earthdata.nasa.gov/wms/epsg4326/best/wms.cgi           영상(GetMap, EPSG:4326, 4096×2048)
https://gibs.earthdata.nasa.gov/wmts/epsg4326/best/1.0.0/{레이어}/default/2km/all/{시작}--{끝}.xml   관측 시각 목록(DescribeDomains)
https://gibs.earthdata.nasa.gov/colormaps/v1.3/Clean_Longwave_Infrared_Window_Band.xml          색 → 섭씨 표
https://view.eumetsat.int/geoserver/ows                              영상(GetMap, 직하점 ±80°를 2×2 조각으로, 조각당 약 910px)
```

**처리 흐름** (`CloudMapRefreshScheduler`, 10분마다)

```
GeoRingFrames.refresh: 위성마다 이미 가진 것보다 새 영상이 있으면 받는다
  GIBS      → 시각 목록에서 최신 시각 → 영상(빈 영상이면 최대 3번 다시)
  EUMETView → 지금부터 관측 간격씩 거슬러 64×32로 있는지만 묻고, 있으면 전체 크기로
  GIBS 색 → 가장 가까운 표 색의 섭씨 → 3×3 중앙값(점 잡음 제거)
  3시간 넘은 영상은 버림
CloudComposer.compose:
  EUMETView 밝기 → 섭씨: 겹치는 GIBS 영상과 최소제곱 직선(실패하면 기본값)
  칸마다 위성별 가중치 max(cos 천정각 - 0.15, 0)^3 으로 섭씨 평균 → 구름 밀도
  (바다 칸의 맑음 기준 = max(위도 기준, 최근 12~24시간 최고 온도 - 3°C). ClearSkyBackground)
  어느 위성도 못 본 칸은 GMGSI로 채움
→ JPEG → CloudMapStore → GET /api/globe/clouds (X-Clouds-Observed-At = 쓰인 영상 중 가장 오래된 관측 시각,
  X-Clouds-Sources = 제공 기관)
프론트: 10분마다 다시 받고, 관측 시각이 바뀌었을 때만 텍스처를 갈아 끼운다
```

**해상도** (2026-11-06): 2048×1024(1픽셀 약 20km)에 잡음 제거(3×3 중앙값)까지 거치면 열대 소나기구름이 결 없는
둥근 덩어리로 보였다. 히마와리 원본(약 2.5km)과 나란히 놓으면 차이가 분명해 4096×2048(약 10km)로 올렸다.
EUMETView는 지구 전체처럼 거칠게(1픽셀 0.18°, 2048) 요청하면 미리 줄여 둔 자료로 그려 구름이 큰 사각형으로 나오고
(처음 합성을 넣을 때부터 있던 문제), 4096 한 장은 200초 넘게 걸린다. 위성이 보는 범위(직하점 ±80°)를 2×2 조각으로
나눠 라스와 같은 촘촘함으로 받는다. 조각 하나 MTG 약 10초, IODC 40~56초. 끊긴 연결은 한 번 다시 묻고, 읽기 제한은
120초. 한 회차가 4~6분 걸려 스케줄을 '끝나고 10분 뒤'에서 '시작 기준 10분마다'로 바꿨다.

**바다의 맑은 날 온도** (2026-11-07): 위도마다 하나인 맑음 기준(위도 40° 약 2°C)은 겨울 땅이 구름으로 잡히지
않게 낮춘 값이라, 훨씬 따뜻한 바다(11월 동해 약 15°C) 위의 낮은 구름(꼭대기 -3°C 안팎)이 거의 지워졌다. 같은 시각
히마와리 적외선 원본에는 보이는데 합성본에서 밀도 0.16이었다. 바다 칸만 그 칸의 최근 최고 온도를 기준으로 쓴다.
땅은 낮밤 차이가 15~20°C라 같은 방식이면 맑은 밤이 통째로 구름이 되므로 위도 기준 그대로다. 육지·바다 구분은
GIBS `OSM_Land_Water_Map`(4096×2048, `backend/src/main/resources/clouds/sea-mask.png`). 진하기 곡선도 바꿔 기준보다
15°C 차가우면 0.5가 되게 했다(예전 곡선에서는 0.3 남짓). 가장 짙은 온도는 위도 기준에 묶어 열대 소나기구름이 다시
일찍 하얘지지 않는다. 시제품(일본 부근 455×284, 히마와리 24시간): 화면 평균 불투명도 0.080 → 0.133.
기록은 메모리에만 있어 재시작 뒤 하루 동안은 효과가 점점 커진다.

**막혔던 점과 판단**
- GIBS 영상의 색이 색상표와 정확히 일치하는 픽셀이 60%대였다. 원본 해상도 타일도 같았다(축소본에서 이웃
  색이 섞인다). 가장 가까운 색으로 되돌리고 3×3 중앙값으로 점 잡음을 걷어냈다. 이 필터 하나로 EUMETView
  환산 오차도 15°C → 6.5°C로 줄었다. 오차 대부분이 GIBS 쪽 잡음이었다.
- GIBS는 같은 주소를 여러 번 물으면 빈 영상과 정상 영상이 섞여 왔다(GOES-West, 세 번 중 1~2번 정상).
  작은 크기로 있는지만 묻는 방식은 거의 늘 빈 영상이라 쓸 수 없어서, 시각 목록(DescribeDomains)으로 최신 시각을
  정하고 빈 영상이면 다시 묻는다.
- EUMETView는 없는 시각을 물으면 HTTP 200에 XML 예외를 주고, 있는 시각이면 실제로 쓴 시각을 `Warning` 헤더에
  준다("99 Nearest value used: time=...").
- 위성마다 관측 시각이 최대 20분 다르다. 구름은 시속 30~60km로 움직여 20분이면 10~20km이고, 이미지 한 칸(약
  20km) 안이라 위성마다 최신 영상을 그대로 쓴다.
- 위성 원판 가장자리(천정각 81° 밖)는 쓰지 않는다. 비스듬히 보면 해상도가 떨어지고 구름이 두꺼워 보인다.

**라이선스**
- GIBS: NASA가 공개하는 영상. 출처 표기를 요청한다.
- EUMETView: EUMETSAT 데이터 정책(2026-01판) 4조에서 SEVIRI·FCI의 Advanced Image Products를 Core로 분류하고,
  정의에서 이를 "Web Map Services 등에 쓰이는 단일 채널 시각화, 원본 수치 미포함"이라 한다. Core는 5조에 따라
  CC-BY-4.0으로 누구나 무료로 재배포할 수 있고, 6.3조의 표기("Contains modified EUMETSAT Meteosat data 연도")가
  필요하다. 같은 Meteosat이라도 1시간 미만 지연의 원본 수치 파일은 유료(14조)라 쓰지 않는다.
- EUMETView 자체의 이용 약관·호출 한도 문서는 찾지 못했다. 10분에 영상 두 장 정도만 받는다.

## 실시간 구름 바탕: NOAA GMGSI

**무엇** — Global Mosaic of Geostationary Satellite Imagery. NOAA가 정지궤도 기상위성 다섯 기
(GOES-East·West, Himawari, Meteosat 두 기)의 장파 적외선(약 10.3~10.8 µm 대역) 영상을 이어 붙인
전 지구 합성 영상이다. 적외선이라 밤에도 구름이 보인다.

**어디서** — AWS의 NOAA 공개 데이터 버킷. 인증과 키가 없다.

```
https://noaa-gmgsi-pds.s3.amazonaws.com/?list-type=2&prefix=GMGSI_LW/yyyy/MM/dd/HH/   목록(S3 ListObjectsV2)
https://noaa-gmgsi-pds.s3.amazonaws.com/GMGSI_LW/yyyy/MM/dd/HH/GLOBCOMPLIR_..._s{관측 시작}_e..._c....nc
```

**형식** (2026-10-28 파일로 확인)

| 항목 | 값 |
| --- | --- |
| 파일 | NetCDF4(HDF5), 약 7MB, gzip 압축 청크 |
| 격자 | `data[1][3000][4999]` float32. 0~255로 정규화한 밝기온도(차가울수록 큼) |
| 투영 | **메르카토르.** 행 간격이 위도로는 0.072°~0.021°로 변하고 메르카토르 좌표로는 일정하다 |
| 범위 | 위도 약 ±72.7°, 경도 360°(0열이 -180°) |
| 갱신 | 매시 정각 관측분이 약 35분 뒤에 올라온다 |

**처리 흐름**

```
CloudMapRefreshScheduler (10분마다)
  → GmgsiClient.latestKey: 지금·1시간 전·2시간 전 폴더 목록에서 최신 키
  → 이미 처리한 키면 끝 (실제 다운로드는 시간당 1회)
  → GmgsiClient.download: 임시 파일로 받기 (40MB 상한, 키 모양 검증)
  → GmgsiFiles.renderJpeg: 256행씩 읽어 메르카토르 → 등장방형 재투영, 밝기 → 구름 밀도, 2048×1024 흑백 JPEG
  → CloudMapStore (메모리)
GET /api/globe/clouds → JPEG + X-Clouds-Observed-At 헤더 (없으면 404)
홈 라스 → 받으면 위도 60°까지 실시간 구름, 70° 너머는 정적 구름. 404·실패면 정적 구름만
```

**측정** — 변환 2.1초(LattePanda Alpha, 3회 중 2~3회째), 결과 383KB. 다운로드는 시간당 약 7MB.

**구름 판정** — 구름 꼭대기는 차갑고 지표는 따뜻하다는 것만으로 가른다. 고위도는 지표 자체가
차가워 구름처럼 보이므로 문턱을 위도에 따라 올린다(적도 112 → 위도 70° 이상 150, 0~255 기준).
실제 파일을 라스에 씌워 보며 정했다. 겨울 고원·극지 얼음처럼 차가운 지표는 옅은 구름으로 보일 수 있다.

**한계와 판단**
- 1시간 단위다. 실시간 영상(10분 단위)을 원하면 GIBS의 GOES·Himawari 레이어를 쓸 수 있지만,
  GIBS에는 유럽·아프리카·인도양을 덮는 Meteosat 레이어가 없어 그 지역이 빈다(아래 후보 표).
- 서버가 받아 가공한다. 브라우저가 직접 받게 하면 사용자마다 7MB를 받아야 하고, NetCDF를 브라우저에서
  풀어야 하며, 외부 장애가 그대로 사용자에게 보인다.
- 이미지는 메모리에만 둔다. 재시작하면 기동 직후 수집이 다시 채우고, 그 사이에는 정적 구름이 보인다.
- 주소에 확장자를 붙이지 않는다. `.jpg`면 Cloudflare가 엣지에 캐시하는데, CORS 헤더 없이 캐시된 응답이
  다른 출처 요청에 나가면 브라우저가 텍스처를 거부한다.
- 라이선스: NOAA가 NODD(Open Data Dissemination)로 공개 배포하는 미국 정부 자료다. 합성에 포함된
  Meteosat 자료는 EUMETSAT 데이터 정책(2026-01판)을 따른다. 정각 기준의 시간 단위 Level 1 자료와
  Web Map Service용 단일 채널 시각화(Advanced Image Product)는 Core로 분류되어 CC-BY-4.0으로 재배포가
  허용되고, 6.3조에 따라 "[Contains modified] EUMETSAT Meteosat data [연도]" 표기가 필요하다. 그래서 실시간
  구름일 때 출처 표기에 이 문구를 붙인다. 1시간 미만 지연의 비정각 Level 1 원본 수치 자료는 Recommended로,
  유료 라이선스(최종 사용자 연 4,000유로부터)이며 원본 수치의 재배포가 금지된다(4·5·6·14조).

**의존성** — HDF5 파일을 순수 자바로 읽으려고 `io.jhdf:jhdf:0.13.0`(MIT)을 쓴다. 네이티브 라이브러리가
필요 없다. 이 파일의 루트 속성에는 원본 위성 파일 목록이 14KB 문자열로 들어 있어 jhdf가 루트 속성을
읽다 실패한다. 그래서 위도 범위를 전역 속성 대신 `lat` 배열의 첫 값과 끝 값에서 읽는다.

## 낮과 밤

외부 데이터가 아니다. 태양이 머리 위에 있는 지점(태양 직하점)을 현재 시각만으로 계산한다(`frontend/src/lib/sun.ts`).

- **공식**: 미국 해군천문대 천문연감(Astronomical Almanac)의 저정밀 태양 위치식. 1950~2050년에 오차 약 0.01°다.
  NOAA의 일반 태양 위치식도 검토했는데, 2026~2027년을 7시간 간격으로 비교하니 위도가 최대 0.44°, 경도가 0.2° 어긋나 쓰지 않았다.
- **확인**: 2026-06-21 08:24 UTC(하지)에 위도 23.44°, 2026-03-20 14:46 UTC(춘분)에 위도 0.00°.
- **자전**: 실제와 같이 24시간에 한 바퀴다. 직하점을 매 프레임 구하고 정면이 그만큼 따라 돌게 해서, 화면에서 태양 방향은
  고정되고 지구가 그 아래에서 돌며 낮·밤 경계가 지표 위를 시간당 15°씩 지나간다. 자전각을 경과 시간의 누적이 아니라
  현재 시각에서 바로 구해, 탭이 백그라운드였다 돌아와도 태양과 어긋나지 않는다. 사용자가 끌어 돌리면 보는 위치만 바뀐다.
- **도시 불빛**: 밤 지역의 불빛(VIIRS Black Marble)은 플레어와 겹쳐 구분이 어려워 기본은 끈다.
  화면 오른쪽 위 설정에서 켤 수 있다. 이 설정은 브라우저(localStorage)에만 저장된다.
- **지도에도 같은 효과**: 지도(MapLibre)는 위성사진 타일을 그대로 붙여 지구 전체가 대낮으로 보였고, 홈 라스에서 확대해
  넘어가는 순간 차이가 컸다. 커스텀 레이어(`frontend/src/components/globe/mapDaylightLayer.ts`)가 같은 태양 직하점·실시간
  구름·도시 불빛 설정으로 밤 그늘과 구름을 타일 위에 덮는다. 국경선·지명·플레어는 그 위에 그려 밤에도 보인다.
  지도는 확대해 읽는 화면이라 줌 4까지만 온전히 보이고 줌 6에서 사라진다. 바다 햇빛 반사와 가장자리 대기 산란은
  옮기지 않았다(카메라 방향 계산이 따로 필요하고, 바깥 대기광은 이미 있다). 구름 출처 표기는 지도 표기(ⓘ)에 함께 단다.

## 브라우저가 직접 부르는 외부 서비스

브라우저가 직접 요청하면 사용자의 IP가 그 서비스에 전달된다.

- **Esri 타일**: 지도를 확대할 때마다. 출처 표기는 지도 오른쪽 아래(MapLibre)에 있다.
- **OpenFreeMap**: 지명·경계 벡터 타일과 글꼴.
- **ipwho.is, geojs.io**: 첫 화면을 사용자 근처로 돌리려고 IP로 대략의 위치를 묻는다. 두 곳에 물어 지역을 더
  구체적으로 답한 쪽을 쓰고, 제공자마다 4초 안에 답이 없으면 끊는다. 둘 다 실패하면 기본 위치로 시작한다. 비로그인 공개 범위를 정하는
  접속 국가는 이 값이 아니라 서버가 받는 Cloudflare 헤더로 판정한다(클라이언트가 국가를 주장하게 두면
  그대로 우회된다).

## 서울시 실시간 돌발정보 → 플레어

```
SeoulIncidentScheduler (10분, fixedRate)
  → SeoulIncidentClient: http://openapi.seoul.go.kr:8088/{키}/xml/AccInfo/{시작}/{끝}/  (XML만 됨, 1,000건씩)
      총 건수(list_total_count) = 받은 행 수일 때만 "완전한 목록"
  → SeoulIncidents: 유형 고르기 → 중부원점 TM(EPSG:5181) → 위경도 → 서울 범위 밖이면 버림
  → ExternalFlareSyncService.sync: 처음 보는 acc_id는 생성, 있으면 갱신(끝났던 플레어는 되살림),
      완전한 목록일 때만 빠진 플레어를 종료 → FlareChanged → 커밋 후 Redis → /topic/flares
```

- **작성자**: 시스템 계정 `서울시 교통정보`(provider SYSTEM, 로그인 경로 없음). 플레어의 `origin`은 `API`이고 상세 화면에
  "공공데이터 · 서울시 교통정보"로 보인다. 공공누리 1유형의 출처 표시를 이 자리에서 한다.
- **넣는 유형**: 교통사고·차량고장·보행사고·낙하물(사고, 차량화재는 화재), 하루 안에 끝나는 공사(기타),
  행사 통제 10B01(군중). 장기 공사(2030년까지인 건도 있다)와 집회·행진(10B02), 모르는 유형은 넣지 않는다.
  유형 코드 전체 목록은 운영 키로 확인해 보강해야 한다.
- **수명**: 종료 예정 시각. 단 목록에 있는 동안은 적어도 수집 두 번(20분) 뒤까지 산다. 공감해도 늘지 않는다.
- **중복**: `(source, external_id)` 유니크 인덱스(V8). 동시에 네 번 동기화해도 플레어는 하나(ExternalFlareSyncTest).
- **좌표**: `grs80tm_x/y`. 원점 38°N·127°E, 가산 x 200,000 / y 500,000(EPSG:5181). 실제 응답 5건을 풀어 봉은교·청계천
  등 설명된 장소에 떨어지는 것을 확인했다. 변환은 `KoreaTm`(Snyder 공식, 왕복 오차 1cm 미만).
- **보안**: HTTPS가 없어 인증키가 평문으로 오간다(공개 데이터 읽기 전용, 재발급 가능). 예외 메시지에 실리는 요청
  주소에서 키를 지우고 로그에 남긴다. 응답 XML은 DTD를 막아 읽는다(XXE).
- **실제 응답에서 확인한 함정**: 시각이 `1000`(HHmm)과 `130000`(HHmmss)으로 섞여 온다. JSON을 요청하면 오류다.
  공개 샘플키는 한 번에 5건까지라 로컬은 `page-size: 5`.

## 스키장 개장 정보 → 플레어

```
resources/ski/season.json  (시즌, 유효 기한, 스키장마다 좌표 · 개장일 · 폐장일 · 출처)
  → SkiSeasonScheduler: 기동 시 한 번 읽고 검사(날짜에 출처 필수, 국내 좌표, id 중복) — 잘못되면 기동 실패
      1시간마다 오늘(한국 날짜)로 SkiResorts.toDrafts
  → ExternalFlareSyncService.sync(source SKI_SEASON, 완전한 목록) → FlareChanged → 커밋 후 Redis → /topic/flares
```

- **왜 파일인가**: 스키장 개장일을 주는 공공 API가 없다. 날짜는 리조트 공지와 기사에만 있는데, 기사를 자동으로 모아 AI로
  날짜를 뽑으면 포털 검색 API 특약(AI 입력 금지)과 언론사 사이트 무단 수집 문제에 걸린다. 그래서 사람이 공지를 확인해
  날짜와 출처를 적고, 서버는 날짜에 맞춰 켜고 끄는 일만 자동으로 한다.
- **날짜는 리조트 공식 누리집 공지만**(이미지 안내 포함). 언론 보도와 블로그는 쓰지 않는다. 레저/행사 정보는 운영 주체가
  직접 밝힌 것만 전한다. 언론 목표일을 잠시 받아 봤는데, 모나용평은 보도(11월 27일)와 같은 날 올라온 공식 공지(11월 22일)가
  달랐다(2026-11-17). 날짜가 없는 스키장은 플레어를 만들지 않는다. 글의 날짜에는 "리조트 공지 기준, 날씨에 따라 바뀔 수
  있음"을 붙인다.
- 누리집이 자동 접근을 막아 둔 곳(휘닉스의 목록 API 등)은 우회하지 않고, 사람이 화면으로 본 공지 주소를 출처로 적는다.
- **채팅 없음**: 외부 데이터의 레저/행사 플레어는 채팅을 닫는다(`Flare.isChatOpen`, 서버가 `CHAT_CLOSED`로 거절).
- **표시 기간**: 개장 30일 전부터 "개장 예정", 개장일부터 "개장". 폐장일이 발표되면 그날 자정(한국 시각)까지, 아니면 파일의
  `validUntil`까지. 날짜를 지우면(연기) 다음 주기에 플레어가 끝난다.
- **담는 것**: 시설 이름·날짜·출처 이름(예: "오크밸리 공식 사이트 공지사항(2026-09-09)"). 공지 주소와 확인한 날은 `season.json`에만 둔다. 특정 인물에 관한 내용은 넣지 않는다.
- **좌표**: OpenStreetMap Nominatim의 스키장 영역(landuse=winter_sports) 대표점. 영역이 없는 곳은 리조트 시설 점을 썼다
  (지산·에덴밸리는 호텔, 오크밸리는 리조트 입구 정류장 — 슬로프와 1km 안팎 차이).
- **갱신 방법**: 개장 공지가 나오면 `opening`과 `source`를 채워 push한다. 새 이미지가 뜨면 다음 주기(최대 1시간)에 반영된다.

## 파리 행사 → 장소별 플레어

```
ParisEventsScheduler (1시간)
  → ParisEventsClient: {base}/exports/json?select=id,address_name,lat_lon,qfap_tags,occurrences
                       &where=date_end >= now() AND date_start <= now(days=1) AND lat_lon is not null
  → ParisEvents: 오늘(파리 날짜) 안에 시작하고 아직 안 끝난 회차가 있는 장소만, 장소별로 묶어 행사 수가 많은 순 60곳
  → ExternalFlareSyncService.sync(source PARIS_QFAP, 완전한 목록)
```

- **해외는 인증키가 필요 없는 출처부터**(2026-11-18 결정). 나라마다 키를 받아 넣을 수 없어서다. 런던 TfL·샌프란시스코 511은 키가 필요해 보류.
- **행사 이름을 받지 않는다.** 공연명에 출연자 이름이 들어가는 일이 많아 특정 인물 정보 금지 원칙에 걸린다. `select`로 제목·설명·연락처를
  요청하지 않고, 플레어는 "장소 + 오늘의 행사 N건 + 분류(최대 셋) + 현지 시각"으로 만든다. 장소 이름은 시설 이름이다.
- **양**: 시작·끝 날짜로만 고르면 진행 중이 1,100건이 넘는다(대부분 매주 정해진 요일에만 열림). 오늘 회차로 고르면 240건 안팎, 장소로 묶으면
  180곳 안팎이다. 지구본은 한 번에 최대 500개를 그리므로 `max-venues: 60`으로 자른다.
- **수명**: 그 장소의 오늘 마지막 회차가 끝나는 시각. 같은 장소는 날이 바뀌어도 같은 외부 ID(장소 이름·좌표의 해시)라 플레어가 이어진다.
- **레저/행사**라 채팅과 사실 확인을 받지 않는다(D-19·D-20).
- **ODbL**: 지도 하단과 홈 지구본 출처에 "파리 행사: Ville de Paris (ODbL)"를 붙인다. 우리 API(`/api/flares`)가 이 데이터에서 나온 값(장소·좌표·
  시각·분류)을 내보내므로, 그 부분은 ODbL 조건으로 쓸 수 있다는 것이 원본 라이선스의 요구다(같은 조건 공유).
- **원본의 함정**: 겨울 날짜인데 회차에 서머타임 오프셋(+02:00)이 붙은 것이 있어 자정 회차가 전날로 읽힌다. 그래서 "오늘 시작"이 아니라
  "오늘 끝나기 전에 시작하고 지금 이후에 끝남"으로 고른다.

## 기상청 지진정보 → 지구본의 지진

```
KmaQuakeScheduler (1분, fixedRate)
  → KmaQuakeClient: https://apis.data.go.kr/1360000/EqkInfoService/getEqkMsg?serviceKey=…&dataType=JSON
      발표 날짜(fromTmFc~toTmFc)로 24시간 전이 걸친 날부터 오늘까지, 100건씩 최대 5쪽 → 진앙시가 최근 24시간인 것만 남김
      같은 지진의 통보(조기경보 → 지진정보 → 재통보)는 진앙시 2분·거리 100km 안이면 하나로, 가장 늦은 발표를 남김
  → QuakeStore (메모리, 실패하면 그대로)
  → GET /api/globe/quakes (공개, 30초 캐시) → 브라우저가 1분마다 물음
```

- **플레어가 아니다.** 사람이 남기는 플레어와 섞지 않고 따로 그린다: 진앙의 점과 그 둘레로 퍼지는 원(화면 픽셀 크기,
  `frontend/…/globe/quakeShader.ts`). 옵션의 '공공 정보' 스위치를 함께 따른다.
- **한반도 인근은 기상청만, 같은 지진이면 기상청**(2026-11-18 결정, D-18). 지진·지진해일·화산의 관측 및 경보에 관한 법률 제16조는
  기상청장 외의 자가 지진의 관측 결과와 특보를 "발표"하는 것을 막는다(제28조 벌칙). 해외 공식 기관이 공개한 값을 출처와 함께 옮기는
  것이 "발표"인지는 정의·해석례가 없다. 그래서 그 조항이 막으려는 혼란(공식 창구와 다른 값)이 생길 수 있는 곳은 기상청만 쓰고, 그
  밖에서만 USGS를 더한다(`QuakeSources`): 북위 32~41°·동경 122~132° 안의 해외 기관 지진은 버리고, 구역 밖이라도 기상청이 같은
  지진(진앙시 2분·거리 100km 안)을 통보했으면 기상청 것을 쓴다. 기상청에 서면 질의해 해석을 받는 것이 남은 일이다.
- 값은 발표 기관의 원문 그대로 옮기고(USGS 위치 설명은 영어 원문), 위험도 같은 판단을 붙이지 않는다. 원의 크기·밝기는 규모와 경과
  시간을 보이게 하는 표현 규칙일 뿐 진동이 전달되는 범위를 계산한 값이 아니다. 영향 범위로 읽히지 않게 원은 지표면 거리가 아니라
  화면 픽셀 크기로 그린다. 예보·특보(태풍 진로 포함)는 기상법 제17조라 해외 기관 것을 쓰지 않는다.
- **USGS**: `https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/4.5_day.geojson` — 키 없음, 미국 정부 공개 자료(퍼블릭
  도메인, 출처 표기 요청). 지난 하루 규모 4.5 이상(하루 10건 안팎), 2분마다. `type`이 earthquake가 아닌 사건(채석 발파 등)은 뺀다.
  출처는 지진마다(`source`) 정보 창에, 그리고 지도 하단에 표기한다.
- **표시 기준: 규모 3.0 이상**(`earth.quakes.min-magnitude`, 2026-11-18). 피해 판단이 아니라 표시 범위다 — 2점대는 대부분 느끼지 못하고
  3점대는 가까운 곳에서 느끼는 정도다. 규모를 모르는 통보는 뺀다. 같은 지진 판단은 거르기 전의 기상청 목록으로 해, 기상청이 2점대로 낸
  지진을 해외 기관 값이 대신하지 않게 한다.
- **범위**: 국내 지진, 그리고 기상청이 통보하는 국외 지진만(동아시아 북위 21~45°·동경 110~145°는 규모 5.0 이상, 그 밖은 6.0 이상).
  지진해일 통보(`getTsunamiMsg`)와 화산은 아직 넣지 않았다.
- **한도**: 일일 10,000회. 1분 주기면 하루 1,440회(쪽이 늘어도 평소 1쪽).
- **보안**: 인증키(Decoding)는 `KMA_OPENAPI_KEY`, 기본값 없음(비어 있으면 기동 실패). 쿼리 문자열에 실리므로 예외 메시지에서
  키를 지우고 로그에 남긴다. 인증 오류는 JSON을 요청해도 게이트웨이가 XML(`returnAuthMsg`)로 답한다.
- **위치정보법**: 지진 발생 위치는 개인위치정보가 아니고, 이 서비스는 이용자 위치를 서버로 받지 않는다. 그래서 위치기반서비스사업
  신고(위치정보법 제9조 제1항, 개인위치정보를 대상으로 하지 않는 사업은 제외) 대상이 아니다.
- **통보종류 코드(fcTp)**: 공식 문서에 뜻이 없다. 운영 첫 응답(2026-11-16)에서 `2` = 국외(일본 도야마현 규모 5.1), `3` = 국내
  (북한 남포 앞바다 규모 2.4)를 확인했다. `14` = 지진속보(자동 조기 분석) — 같은 지진의 `3`이 "지진속보를 수동으로 분석한
  상세정보"로 뒤따른다(2026-11-17 경북 상주 규모 3.6). **2·3만 보여 준다.** Earth는 예보·특보를 하지 않는다(2026-11-18 결정, 기상청 것을 옮기는
  것도 포함) — 조기경보처럼 경보 성격의 통보가 섞여 와도 빼고, 처음 보는 코드는 경고 로그(`관측 정보가 아닌 종류(fcTp=…)`)로 남긴다.
- **실제 응답에서 확인한 것**: 숫자 항목이 숫자로 온다. 국외 지진의 참고사항에 "발생시각, 규모, 발생위치, 발생깊이는 일본기상청(JMA)
  분석결과임"처럼 원 분석 기관이 적혀 오므로 그대로 보여 준다. 참고사항은 줄바꿈(`\n`)으로 항목을 나눈다.
