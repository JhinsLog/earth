## 1. 실시간 전파 — 롤백된 데이터가 화면에 뜨지 않게

**문제** — 별 등록 트랜잭션 **안에서** Redis로 발행하고 있었다. 커밋 전에 예외가 나면 DB는 롤백되지만
pub/sub 메시지는 이미 나가, 존재하지 않는 별이 모든 접속자 화면에 뜬다. pub/sub에는 롤백이 없다.

**선택** — 서비스는 도메인 이벤트(`EventChanged`, `ChatMessagePosted`)만 발행하고,
`@TransactionalEventListener(AFTER_COMMIT)`가 Redis로 내보낸다. "커밋된 뒤에만 나간다"를 사람이 지키는
순서가 아니라 **구조로** 강제했다. 지역 구독 알림 생성도 커밋 뒤로 옮겨, 부가 기능의 실패가 사용자가 쓴 별을
롤백시키지 않게 했다(D-1, D-2).

**왜 Redis를 거치나** — STOMP 브로드캐스트를 서비스에서 직접 하면 그 인스턴스에 붙은 클라이언트에게만 간다.
모든 인스턴스가 같은 Redis 채널을 구독하면 수평 확장 시 코드 변경이 없다.

**남긴 한계** — 커밋은 됐는데 발행이 실패하는 경우(유실)는 남는다. 아웃박스 패턴이 정석이지만 현재 규모에서는
보류했고, 새로고침하면 DB에서 다시 보인다.

## 2. 동시성 — "확인 후 행동"이 뚫리는 세 곳

| | 문제 | 해결 | 검증(Testcontainers) |
| --- | --- | --- | --- |
| 시간당 등록 한도 (D-3) | READ COMMITTED에서 동시 요청이 같은 카운트를 봄. **한도 5에 동시 15건 → 11건 저장** | 검사 전에 작성자 행 `PESSIMISTIC_WRITE` 잠금 | 수정 후 정확히 5건 |
| 공감 수 · 수명 연장 (D-4) | 읽고-계산하고-쓰기. **서로 다른 10명 동시 공감 → 공감 수 1** (수명 연장도 함께 유실) | 별 행 잠금 후 엔티티 메서드로 갱신 | 공감 수 · 만료 시각 모두 일치 |
| 공감 취소 (D-5) | 취소가 수명을 안 줄여 **공감·취소 반복으로 혼자 12시간 상한까지** 연장 가능 | 공감 때 실제 늘어난 초(`granted_seconds`)를 기록하고 취소 때 정확히 그만큼 회수 | 10회 반복 후 원복, 유일한 공감 취소 시 소멸 |

- SQL 원자 증가(`SET count = count + 1`)와 낙관적 잠금도 비교했다. 원자 증가는 수명 상한 규칙이 SQL로 새어 나가고,
  낙관적 잠금은 사용자에게 "다시 눌러 주세요"를 보이게 된다. 동시성 전략을 행 잠금 하나로 통일했다.
- 채팅 도배 제한은 Redis `INCR`(행동 후 확인)이라 같은 문제가 없다는 점도 구분해 두었다.

## 3. 공간 쿼리 — 측정으로 인덱스를 골랐다

**문제** — 프론트가 범위 조회를 쓰지 않고 항상 전 세계 최신 500개를 받았다. 범위 쿼리는 LIMIT이 없고,
날짜변경선을 넘는 화면에서 경도 조건이 깨졌다(D-6).

**측정 조건** — PostgreSQL 별도 컨테이너, 이력 100만 행 + 보이는 별 20만(한국 70%), 7회 중앙값.

| 쿼리 | 처음 | 쿼리 수정 후 | 인덱스(최신순 + 위경도 부분 인덱스) 후 |
| --- | --- | --- | --- |
| 한국 범위 | 172 ms, 14만 행 반환, 정렬이 디스크로 넘침 | 107 ms, 500행, 메모리 top-N | **1.3 ms** |
| 전 세계 최신 500 | 45.2 ms | — | **0.9 ms** |
| 서울 / 유럽 | 12.7 / 8.8 ms | — | **2.5 / 0.8 ms** |
| 날짜변경선 | 동쪽 절반 누락 | 14 ms, 378행(BitmapOr) | **2.8 ms** |

- 후보 다섯(기존 · 최신순 · 위경도 · GiST · 최신순+위경도)을 모두 부분 인덱스(`status='ACTIVE'`)로 비교했다.
  빽빽한 범위는 최신순으로 걷다 500개에서 멈추고, 성긴 범위는 위경도로 해당 행만 읽는다. 둘을 함께 두면
  플래너가 통계로 고른다. GiST는 점의 사각형 검색에서 B-tree보다 나은 점이 없었다.
- 쓰이지 않던 기존 인덱스 두 개(36 MB, 8 MB)는 지웠다.
- **범용 계획 문제** — JDBC가 반복 쿼리를 서버 측 준비문으로 바꾸면 PostgreSQL이 범위를 보지 않는 범용 계획에
  고정돼, 한국 범위가 436 ms까지 갔다. 앱 경로에서 15회 중 6회 재현(`pg_prepared_statements`)한 뒤, 범위 조회
  트랜잭션에서만 `plan_cache_mode = force_custom_plan`을 걸었다(계획 비용 0.2~0.3 ms).
- `expires_at > now()` 부분 인덱스는 만들 수 없다(`now()`는 IMMUTABLE이 아님). 그래서 만료 스케줄러가
  "시간 경과"를 "행 변경(`status`)"으로 바꿔 인덱스가 따라오게 하고, 정확성은 조회 시점 조건이 지킨다.

## 4. 접근 제어 — REST와 실시간 피드를 같은 기준으로

**규칙** — 로그인하면 전부. 비로그인은 접속 국가 안의 별만 상세, 나머지는 위치와 존재만(`restricted`).

- **국가 판정** — Natural Earth 10m 국경(한국 관점)을 Flyway로 적재하고 PostGIS 함수 `country_code_at` 한 곳에서
  판정한다. 육지 폴리곤에 안 걸리는 섬·해안은 12해리 안 최근접 국가로 보정(독도 664 m → KOR, 대한해협 한가운데 →
  없음). 판정은 등록 때 한 번(23~60 ms)만 하고 저장한다(D-8).
- **실시간 누출 차단** — REST만 막으면 같은 정보가 실시간으로 샌다. 실제로 비로그인 연결이 전체 피드를 구독할 수
  있었다. 피드를 `/topic/events`(로그인) · `.public`(위치만) · `.country.{CC}`(자기 국가)로 나누고 구독 시점에
  검사한다. 거부는 예외 대신 프레임을 버려, 허용된 공개 피드까지 끊기지 않게 했다.
- **신뢰 전제** — 접속 국가는 Cloudflare가 엣지에서 붙이는 `CF-IPCountry`. 서버가 Tunnel 뒤에만 있어 클라이언트가
  위조할 경로가 없다. 판정은 서버가 하고, 클라이언트의 주장은 받지 않는다.
- 검증: 실제 WebSocket 연결 테스트에서 구독 검사를 빼면 작성자·내용이 새는 것이 재현되고, 넣으면 막힌다.

## 5. 외부 데이터 동기화 — 서울시 실시간 돌발정보를 별로

API는 "지금 진행 중인 목록 전체"만 주고 종료를 알려 주지 않는다(D-9).

- **스냅샷 비교** — 목록에서 빠지면 종료. 단 **총 건수와 받은 행 수가 같을 때만** 비교해, 일부만 받은 응답으로
  별이 무더기로 꺼지지 않게 했다.
- **중복 방지** — "없으면 생성"은 다중 인스턴스에서 틈이 있다. `(source, external_id)` 유니크 인덱스를 마지막
  방어선으로 두고, 늦은 쪽은 제약 위반으로 롤백된다. 전파는 커밋 후라 실패한 쪽 별은 화면에 뜨지 않는다.
  분산 락은 락 만료 틈 때문에 어차피 DB 제약이 필요해 택하지 않았다. 검증: 동기화 4개 동시 실행 → 별 1개.
- **작성자** — 시스템 계정 + `origin(USER/API)` 컬럼(V8). 작성자를 nullable로 바꾸면 응답·권한·채팅 코드를
  모두 고쳐야 했다.
- **수명** — 종료 예정 시각을 따르되 목록에 있는 동안 최소 20분(수집 두 번)을 보장해 깜빡임을 막았다.
  좌표는 중부원점 TM(GRS80, EPSG:5181) → 위경도로 직접 변환한다(`KoreaTm`). 5186과 원점 오프셋이 달라, 실제 지점과 대조해 5181임을 확인했다.
- 사용자는 설정에서 공공데이터 별을 끌 수 있다. 서버 필터가 아니라 화면에서 거른 이유: 실시간 토픽은 권한
  기준으로 나뉘어 있어 서버에서 거르면 실시간 경로에 같은 규칙을 한 번 더 둬야 한다(D-10).

## 6. 실시간 구름 — 정지궤도 위성 다섯 기 합성

홈 지구본의 구름은 실제 위성 영상이다. 백엔드가 10분마다 GOES-East/West · Himawari(NASA GIBS WMS),
Meteosat 0° · 인도양(EUMETSAT WMS)의 적외선 영상을 받아 한 장으로 합성해 서빙한다.

- 색 → 섭씨 역변환 후 3×3 중앙값으로 잡음 제거. 이 필터로 기관 간 밝기 환산 오차가 **15 °C → 6.5 °C**.
- 칸마다 위성 천정각 가중 평균, 원판 가장자리(81° 밖) 제외, 빈 칸은 NOAA GMGSI로 채움.
- 바다는 칸별 최근 최고 온도를 맑음 기준으로 써 낮은 구름 복원(화면 평균 불투명도 0.080 → 0.133).
- 외부 API의 비정상 응답(같은 요청에 빈 영상이 섞임, HTTP 200에 XML 예외)을 재시도·검증으로 흡수했다.
- 라이선스(EUMETSAT 데이터 정책 조항, CC-BY-4.0 표기)를 확인하고 원본 수치 파일 대신 공개 영상만 쓴다.

## 7. 운영 장애 대응 — 구글 로그인 500

2026-10-14부터 로그인 후 500. 구글이 준 프로필 사진 주소가 `VARCHAR(500)`을 넘었다. 컬럼을 넓히고(V5),
저장 전에 길이를 방어했다. 넘는 URL은 잘라 깨진 링크를 만드는 대신 비우고, 닉네임은 이모지가 쪼개지지 않게
코드 포인트 단위로 자른다. 원칙: **외부 제공자가 정하는 값은 신뢰하지 않고, 부가 정보 때문에 핵심 경로가 실패하지
않는다**(D-7). 테스트하려고 제공자 호출과 DB 저장을 분리했고, 수정 전 5건이 운영과 같은 에러로 실패함을 확인했다.

## 8. 배포와 보안

- **pull 방식 배포** — Actions는 이미지를 올리기만 하고, 홈서버 타이머가 3분마다 새 이미지를 당긴다. GitHub에
  서버 접속 정보가 없어 워크플로가 탈취돼도 서버에 닿지 못한다. 공개 저장소라 self-hosted 러너는 쓰지 않는다.
- **테스트 게이트** — Testcontainers 통합 테스트가 실패하면 이미지가 올라가지 않는다. 인메모리 DB를 쓰지 않는
  이유는 검증 대상이 트랜잭션 격리와 행 잠금이기 때문이다.
- 시크릿에 기본값을 두지 않아 값이 없으면 기동이 실패한다. 개발용 토큰 발급 API는 `local` 프로파일 전용.
- TLS가 Cloudflare 엣지에서 끝나므로 `forward-headers-strategy=framework`로 OAuth `redirect_uri`를 https로 만든다.

## 이력서용 문장

- Spring Boot · STOMP · Redis pub/sub 기반 실시간 3D 지구본 서비스를 1인 개발해 자택 서버에서 운영
- `AFTER_COMMIT` 이벤트 리스너로 브로드캐스트를 커밋 이후로 강제해, 롤백된 데이터가 실시간으로 퍼지는 문제를 구조적으로 차단
- 등록 한도·공감 수의 경합(동시 15건 중 11건 저장, 10명 동시 공감 시 1건 반영)을 Testcontainers로 재현하고 행 잠금으로 해결
- 뷰포트 조회를 측정 기반으로 재설계: 인덱스 후보 5종 비교, 한국 범위 172 ms → 1.3 ms(20만 행), 범용 계획 고정(436 ms) 문제를 찾아 트랜잭션 단위 `force_custom_plan`으로 해결
- PostGIS 국경 판정과 STOMP 토픽 분리로 비로그인 사용자의 공개 범위를 REST · 실시간 양쪽에서 동일하게 적용
- 공공 API 스냅샷 동기화를 유니크 제약 기반으로 다중 인스턴스에서도 중복 없이 구현(동시 실행 4개 → 별 1개)
- 테스트 통과 시에만 이미지를 올리는 CI와, 서버 접속 정보를 외부에 두지 않는 pull 방식 배포 구성

## 알려진 한계

- 커밋 후 발행 실패 시 메시지 유실(아웃박스 미도입). 새로고침하면 복구된다.
- 실시간 연결이 끊긴 동안의 종료 메시지는 재연결 시 다시 받지 않는다. 클라이언트는 만료 시각으로 스스로 정리한다.
- 인스턴스는 현재 1대다. 다중 인스턴스 경로(Redis 릴레이, 유니크 제약)는 테스트로만 검증했다.
- 프론트엔드 자동화 테스트는 없다.
